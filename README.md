# Simwisp

**Your simulators, a little closer.**

A native macOS menu-bar app that brings live iOS and Android simulators into a lightweight browser workspace. Capture, input, and networking run in Swift; the browser stays plain HTML, CSS, and JavaScript.

## At a glance

- **Native capture** — ScreenCaptureKit → VideoToolbox H.264 → WebCodecs, bounded frame buffers, and adaptive pacing up to 60 FPS.
- **Multiple devices** — view iOS and Android simulators side by side, with resizable panels, independent connections and confirmed per-device Stop controls.
- **Real controls** — taps, drags, Home, iOS Shake and App switcher, rotation, appearance, keyboard/text input, and Android Back/Menu/App switcher/two-finger gestures.
- **Menu-bar only** — no normal server window; inspect sessions, permissions, and process usage from the menu.
- **Quiet when idle** — capture and background discovery stop after the final streaming client disconnects. Popup monitoring stops when the popup closes. Terminal I/O uses readiness notifications, not polling.
- **Optional Mac terminals** — login shells with tabs, resizing, themes, reconnect replay and explicit session cleanup. Renderer assets load only when a terminal is opened.
- **A lightweight workspace** — light, dark, and system themes; no frontend frameworks, package installation, external fonts, or CDN dependencies.
- **Paired access** — local-only by default, with optional network sharing and browser pairing.

## Requirements

| Requirement | Purpose |
| --- | --- |
| macOS 15 or newer | Native capture and memory-only HTTPS identity import |
| Current browser with H.264 WebCodecs support | Decode video over trusted HTTPS (Chrome/Edge/Safari; capability checked at connection) |
| Xcode with a working `xcrun swiftc` | Build the app; discover and run iOS simulators |
| Android SDK / Emulator, optional | Discover, boot, and control Android emulators |
| Screen Recording permission | Capture simulator windows |
| Accessibility permission | Send simulator input |

Window capture and Current touch input need a logged-in graphical Mac session and open, unminimized simulator windows. The Android scrcpy capture/input combination does not require a host emulator window.

No Python environment, Bun/Node runtime, or dependency installation is required to build or run Simwisp. The optional terminal renderer (xterm and fit addon) is bundled locally with its licenses.

## Build and run

```bash
git clone https://github.com/egomarker/simwisp.git
cd simwisp
make check
open build/Simwisp.app
```

`make check` compiles the app, bundles the browser resources, ad-hoc signs it, and verifies the signature. The app appears in the menu bar.

**Before rebuilding an existing installation, quit Simwisp from its menu-bar menu.** Keep your simulator windows open.

### Share with another device

```bash
open build/Simwisp.app --args --lan
```

`--args` is an option for macOS's `open` command: everything after it is passed to Simwisp. Here, Simwisp receives `--lan`.

You can also change **Share on local network** in the app's server settings. Saved settings are reused on subsequent launches; omitting `--lan` does not override a previously saved sharing preference.

### Enable Mac terminals

Terminal access is **disabled by default**. Enable **Allow Mac terminal access** in the menu-bar server settings (saved), or opt in for a launch:

```bash
open build/Simwisp.app --args --lan --terminal
```

Refresh your browser, then choose the icon-and-**Terminal** button in the sidebar. There is no bottom terminal bar. Terminals run on the **host Mac**, not inside a simulator. They start a login shell in `--project-dir` (your home directory by default). You can add up to eight tabs, pin the terminal beside simulators, resize it, and adjust its font size.

**Enabling this grants every paired browser shell access as your Mac user.** Use only trusted browsers and networks. `--no-terminal` disables access for a launch, even if it was saved as enabled.

Collapsing the panel preserves tabs. Closing a tab terminates its shell and foreground job; page reloads reconnect to the existing shell. Disconnected shells expire after 30 minutes. While disconnected, PTY reading is suspended; output-producing commands may block when the kernel buffer fills, rather than wasting CPU draining invisible output.

### Connect a browser

1. Open Simwisp's menu-bar panel.
2. Grant Screen Recording and Accessibility access when needed. macOS may require quitting and reopening the app after a permission change.
3. Choose **Export public HTTPS certificate…** and explicitly trust the exported local CA on every client (including this Mac’s browser). See below.
4. Choose **Open workspace**, or **Copy link** to open the **HTTPS** pairing link on another device.
5. Select a running simulator from the sidebar. Use **Add simulator** to boot another device.

### Run with or without a native window

Each available iOS simulator or Android AVD has **Run** and **Run headless** buttons. The new detached-window/play icon starts the selected device without opening its native window: iOS checks `SimRenderServer` processes and, if any are present, asks Yes/No permission to close Simulator.app and all windowed iOS simulators. Yes closes the whole GUI app before `simctl boot`; No cancels. An empty leftover GUI is closed without a warning, and the full device list is refreshed only after the new headless stream displays its first frame, never at boot acknowledgement or boot failure. No renderer helpers are killed. Android adds `-no-window` to its existing emulator launch arguments. Headless iOS opens the exact UUID stream directly but keeps **Booting…** until that stream successfully draws a decoded video frame. Boot acceptance, socket readiness, configuration, heartbeats and packet receipt alone cannot promote the device row or refresh the list. Other launches open the browser view after exact-device discovery; Android matches the AVD identity, not the first new emulator serial.

- Normal **Run** keeps its existing windowed behavior and saved backend choices.
- Android **Run** and **Run headless** launch the emulator with `ANDROID_EMU_ENABLE_CRASH_REPORTING=0` in its child environment. This disables crash reporting for that launch to prevent blocking crash-report prompts, without changing global preferences, deleting old reports or killing helper/emulator processes. Existing mode-specific launch flags are retained.
- **Run headless** selects **Native** for the iOS panel or **Raw** for Android. These headless-session overrides do **not** rewrite saved backend/scaling preferences. Capture failure is reported rather than silently opening a native window. Launch intent is held for the running device session, not saved as a default. After a server restart, an explicit discovery/connect refresh recovers iOS mode only from a complete all-window/AX inventory (including minimized, hidden and other-Space windows); ambiguous inventories stay unknown. Android recovery reads the selected emulator’s checked process flags. The frontend reconciles live panels and session-only choices from fresh API/WebSocket mode, not stale cache. No new timer or per-frame work is added; ordinary one-second discovery ticks never run mode recovery.
- Headless iOS selects **Native input** for touch, keyboard, Home and App switcher. Rotate and Shake use device-scoped actions without a native window; the obsolete notice bar is removed. These source/isolated-tested paths still require explicit live acceptance. Windowed iOS behavior is unchanged.
- Closing a browser panel only closes its stream, **not** the simulator. The separate sidebar **Stop simulator** button shuts down the selected device by UUID/ADB serial, with the same capture-retirement barrier and state confirmation for headless and windowed devices. After iOS Stop, a short pause and fresh `SimRenderServer` check determine whether any windowed iOS simulators remain. If none remain, Simulator.app is closed; other headless devices do not block this GUI cleanup. Pending launches and process-query failures still prevent an unsafe automatic close.

The default port is **4141**. Only one controlling browser connection is supported per device; a new connection replaces the previous one. Keep one controller per device to avoid competing reconnects.

### HTTPS and certificate trust

HTTPS/WSS is the only transport; there is no plaintext or JPEG fallback. On first start, Simwisp generates a private local CA and a server identity using the Mac’s built-in OpenSSL. They persist under `~/Library/Application Support/Simwisp/tls/`, outside the repository; the directory is `0700` and private files are `0600`. Keys are loaded into memory, not imported into your login/system keychain. No certificate trust, package or browser is installed automatically.

Export **only** `Simwisp-Local-CA.cer` using **Export public HTTPS certificate…** in the menu-bar panel, or the public `/simwisp-ca.cer` route. Compare its SHA-256 fingerprint with the native panel before trusting it. **Never share** `root.key`, `server.key`, `server.p12` or `server.passphrase` or delete the CA to solve a browser warning. Each client must deliberately trust the public CA:

- **macOS:** manually import the public certificate in Keychain Access and set its SSL trust; reopen the browser if needed.
- **iPhone/iPad:** explicitly install the transferred public certificate profile, then enable its full trust under **Settings → General → About → Certificate Trust Settings**. Device-management policy may restrict this.
- **Windows/Android:** explicitly import the public CA in the appropriate user/device trusted-root certificate store. Browser and managed-device trust policies differ.

Then open the HTTPS link using a name/IP covered by the certificate. A warning-page bypass is **not** a reliable WebCodecs secure-context solution. Unsupported/insecure browsers show a clear explanation rather than silently switching pipelines. Trusting this CA authorizes certificates signed by this Mac; keep its private key private and enroll only devices you control.

The CA is reused across launches. Server certificates include localhost, the Mac hostname and current interface IPs (including VPN IPv4 addresses); they are renewed before expiry or after address changes on server restart without changing the CA. New interface addresses may require restarting the server. A damaged/expired CA fails closed and needs explicit repair/renewal and client enrollment, not silent replacement. Pairing remains required after TLS trust, and old link tokens/cookie derivation are preserved; old HTTP bookmarks must change to HTTPS.

### iOS Simulator capture: Mac window / Native

Each iOS panel's **Capture** control offers **Mac window** (unchanged default) and **Native** (manual opt-in). Preferences are browser-local, per simulator UDID, in a separate namespace from Android. Switching reconnects only this panel and joins the old Native source before replacement. Android Auto, physical-phone JPEG defaults, all input methods and shared encoder policy are unchanged.

Native reads the selected simulator's CoreSimulator framebuffer IOSurface, then uses the **existing Core Image → VideoToolbox H.264 → SWV1 → HTTPS/WSS → WebCodecs** path. It does not take Mac-window screenshots, encode JPEG, launch a capture helper or register private callbacks. Only an already discovered simulator in the default CoreSimulator device set is admitted; no device is booted, woken or shut down. Xcode can expose several framebuffer ports (main plus secondary planes). Within the selected simulator, Native follows the supplied probes/upstream policy: choose the unique largest live IOSurface by pixel area, independent of port order. Multiple descriptors aliasing the same kernel IOSurface are one candidate; nil/zero-sized planes are inactive. Distinct equally sized largest surfaces remain a visible ambiguity, never an arbitrary first choice. Only exact framebuffer-display identifiers are admitted; format/layout validation still applies to the winner, with no fallback to a smaller plane to hide an error. Missing/private API signature drift, ambiguous largest surfaces, unsupported formats and encoding failures are visible and latched, without a silent capture-backend fallback. Reopen/resume the view after fixing the cause, or explicitly choose Mac window.

Native caches guarded port/descriptor discovery for the **capture-session lifetime**, bounded to **256 discovered IO ports** (duplicate owners share one entry). After initial discovery, healthy reads do **not** invoke updateIOPorts, enumerate ports, re-read identifiers/descriptors, expire metadata on a clock or schedule background audits. Every discovered display descriptor still fetches its **current framebuffer IOSurface on every poll**, with checked ordinary Objective-C/forwarded dispatch; known-plane largest-area/alias/ambiguity and per-frame geometry/layout guards remain. No IOSurface, pixels or unchecked getter IMP is stored by discovery. Real surface-access/ABI/selection errors release metadata and propagate visibly without an immediate hidden retry; the existing stream latches the failure until explicit reopen/resume. All-known-plane unavailability returns nil, releases metadata and permits discovery on a subsequent admitted read; it never refreshes the unchanged **eight-second readable-image deadline**. Busy/torn pixel snapshots happen after discovery and do not invalidate metadata. Close/replacement releases every cached owner/descriptor. **Intentional no-polling tradeoff:** changed port membership, reclassified identifiers or same-port descriptor replacement are not detected while old cached bindings keep returning valid surfaces; an apparently healthy obsolete surface can remain readable until real unavailability/error or explicit reopen. Tests demonstrate this limit; do not claim immediate topology-change detection or all display-reconfiguration compatibility. This source policy removes recurring metadata work, not pixel readback/copy/compare; real FPS/CPU/input improvement still needs separately approved live validation.

**Native Scaling:** directly below Capture, choose **x1** (default), **x0.5** or **x0.25**. The preference is browser-local per simulator, separate from Android scaling, and hidden/ignored for Mac window. It multiplies both original framebuffer dimensions before the existing4096px long-edge cap and resizes on the Mac **before H.264 encoding/transfer**, not just browser CSS. Dimensions round down to whole pixels; odd content sizes use existing even codec padding, cropped away in the browser. For an828×1792 framebuffer the content sizes are828×1792,414×896 and207×448. The full native framebuffer is still read/copied/compared; this reduces prepared/encoded video size, not source readback. Normalized touch still maps to the original matching visible Simulator window, with the existing headless/orientation safety gate. Scale changes reconnect only this panel through joined retirement; Android and Mac-window behavior, Quality/FPS/Data saver defaults are unchanged.

Polling is bounded by admitted output cadence (1–60FPS, existing flow/backpressure limits), with one synchronous read/encode in flight and no capture-frame queue. Each read validates a non-planar32-bit BGRA/BGRX layout, at most8192pixels per edge and64MiB including row padding. Active rows are copied under an IOSurface read lock into owned immutable bytes. Snapshot storage is acquired/allocated **before** locking the producer; packed contiguous rows use one copy, padding is excluded, and BGRX alpha is normalized opaque **after** unlocking owned bytes. No extra vertical flip is applied. IOSurface seeds reject observable copy races but are **not** a freshness oracle: full-visible-byte comparison still detects changes when a producer does not advance its seed. Core Image prepares a new owned encoder buffer only when pixels change.

Native source comparison now keeps **one reusable full-resolution packed reference in the normal path**, not a retained previous Pixels plus a working snapshot. It compares active normalized bytes before overwriting the owned reference; scaling/rendering still uses only coherent owned pixels after unlock. Native Core Image preparation explicitly waits for render completion, and source storage remains immutable until the final Data/CI consumer releases its borrow. Busy in-place writes can invalidate comparison and conservatively force the next coherent preparation, without discarding the independent last-good prepared cache or changing its epoch. This is source-lifetime reduction, not scaled-only comparison or removal of full-resolution readback.

Snapshot storage has **at most three buffers total per capture, including leased buffers retired by layout changes**, each at most64MiB of active pixels. A Data/CI consumer retains an immutable lease: storage is never reused until all consumers release it. Idle oversized/retired storage is freed on layout changes, inactivity and stop; older leased bytes remain valid until their legitimate consumer releases them and still count against the bound. This deliberately retains a bounded warm working set, not a promise of lower RSS or an overnight-leak fix. No producer IOSurface/pixel pointer is retained by the snapshot pool or passed directly to CI/VT. Existing encoder buffers remain separately bounded. Output is aspect-preserving, at most4096px on its long edge, with even codec padding.

**Data saver OFF** produces NEW H.264 frames/PTS from the last readable owned pixels at the requested adaptive output ceiling; encoded packets are never replayed. A transient seed-mismatched copy (or bounded owned-storage pressure) from a still-present, identical validated layout/scale retains that last image, decoder generation and input availability. It does not request a recovery epoch, re-prepare pixels or recreate the encoder. **Data saver ON** may idle H.264 at0FPS during this busy period while continuing to poll; an explicit IDR can encode the same owned image without an epoch change. The no-readable-image deadline advances only on a coherent read, never on cached encodes: **eight seconds without one still fails visibly**. A busy first image has no cache/video/input readiness; changed geometry/layout/scale must not replay mismatched pixels. True absent/inactive surfaces immediately discard cached pixels and require a fresh IDR/epoch on wake, and ABI/layout/encoding errors remain visible and latched. Routine quality/FPS/IDR changes reuse the encoder; real source geometry changes recreate it, even if scaling rounds to the same encoded size. Pause/close/replacement joins in-flight work and releases per-capture references. Framework handles remain process-wide because unloading ObjC code still used by other captures is unsafe; no simulator commands are used for teardown.

Existing `/api/sessions` Native diagnostics distinguish `busy_seed_snapshots`, `busy_storage_snapshots`, `inactive_surfaces` (nil surface returns), `busy_without_cached_image`, `busy_geometry_changes` and `busy_cached_image_encodes`. `dropped_snapshots` remains the aggregate rejected-read count, **not encoder/decoder reset count**. Snapshot allocation/reuse/current/leased/byte/peak counters describe bounded owned storage, not whole-process RAM or exact CPU attribution. Synthetic continuity/ownership checks do not establish real motion FPS, input latency, CPU savings or which reason caused earlier owner-observed losses.


This is **not zero-copy**, and copying/comparing native-resolution pixels can cost significant CPU/memory. The private Xcode API is version-dependent; guarded signatures cannot prove private runtime semantics or GPU producer coherency. The Xcode16.4 compile, inert runtime-fake and synthetic IOSurface/HTTPS/WebCodecs tests do **not** establish real-simulator capture, orientation, locked/headless operation, distinct motion FPS, latency, CPU savings or Safari acceptance. Capture and input are independent. **Quartz remains the default input** and still requires the matching visible Simulator window and permissions; its touch is refused when that window is missing or has mismatched orientation/aspect. The separate opt-in Native input described below is source/inert-tested, not live/headless certified. Do not change defaults or assume live behavior without owner acceptance.

Use `make test-native` and `make test-native-browser` for owned synthetic tests (existing Node22/Chrome for the latter), not real-simulator probes. Runtime architecture attribution is in **Resources/Native/NOTICE** with the Apache2 license, bundled with the app; it credits subdiox/SimKit and its tddworks/baguette ancestry plus the owner-supplied compatibility probes. SimKit itself is not imported and no Xcode upgrade is required by the implementation.

### iOS input backends

The iOS **Backends → Input** picker offers **Quartz** (the unchanged Mac mouse/keyboard route, default) and **Native** independently of Mac-window/Native capture. Input preference is saved per simulator UUID in this browser. A headless iOS view selects Native capture and input for that session only, without rewriting saved preferences; headless Rotate and Shake use device-scoped system actions, not Mac-window shortcuts.

Native input is an original, device-bound CoreSimulator/SimulatorKit HID bridge, selectively informed by SimKit. A continuous single-touch gesture keeps one nonzero identifier from DOWN through MOVEs to UP, including frozen edge routing and authoritative full-display geometry. Coordinates are normalized once, independent of video scaling. Genuine geometry changes cancel the gesture rather than remapping a held finger. Multi-touch is not implemented.

The connection and pointer services are created lazily for the first valid input event on an active, ready stream. There is **no input polling timer or inactive input loop**. Healthy frame processing does not dispatch input or create input resources; only existing capture lifecycle/geometry branches can request teardown. Pause, disconnect, capture unavailability, geometry/backend change and Stop invalidate queued work, attempt releases of held touch/keys/buttons and join cleanup before a same-device replacement or shutdown. New commands remain gated until previous teardown has been processed, and cleanup failures latch instead of admitting another client. Other devices are not joined. Per-session device/client/service references are dropped; safe process-wide framework handles remain pinned, as for Native capture. Cleanup errors are reported, not treated as proof that a guest accepted UP.

Native supports US-layout ASCII text (up to1024 bytes per request), named navigation keys, Home and App switcher. Unsupported Unicode/controls fail before partially typing; choose Quartz for its existing Unicode paste behavior. Native does not focus a Mac window, use the clipboard, post global Mac HID input or silently fall back to Quartz. Appearance remains the existing device action. For a device explicitly launched or authoritatively recovered as headless, Rotate sends a bounded orientation message to its workspace port, and Shake uses `simctl notify_post <UUID> com.apple.UIKit.SimulatorShake`. Both backend dispatch and frontend panel/backend choices follow the same recovered mode. A merely missing on-screen capture window is NOT treated as headless; windowed controls keep their existing shortcuts, and saved preferences are not rewritten. They release any held touch and share this stream’s cancellation/retirement barrier; windowed actions retain their existing shortcuts. Rotation follows the authoritative framebuffer aspect, never scaled browser pixels. The guest may decline rotation when the foreground app locks orientation; send success is not visual acceptance.

The bridge validates Objective-C method signatures, constructed message allocation/layout/targets and acknowledgements; its bounded one-second ACK wait runs only on the active input worker. **These private APIs are version-dependent.** Installed Xcode16.4 no-device message construction and inert peers do not establish live touch delivery, headless compatibility, actual release acceptance, latency, CPU/RAM neutrality or Safari behavior. Activation/restart and live simulator acceptance require explicit owner approval.

Use `make test-native-input` for inert state/ownership tests, `make test-native-input-builders` for explicitly no-device private message/ABI checks (`make test-native-input-services` selects only its four service-message constructors), and `make test-native-input-browser` for owned synthetic HTTPS/WebCodecs/picker/lifecycle fixtures. Use `make test-headless-ios-controls` for the new orientation/Shake command, cancellation and owned-local-IPC checks. None builds or restarts the app bundle, connects a real HID client or sends input to a simulator.

### Android capture and input backends

Each Android panel has a **Backends** control in its telemetry/footer row. Capture and input are independent:

- **Capture:** Auto / scrcpy / Mac window (ScreenCaptureKit + VideoToolbox) / JPEG (Android emulator JPEG70 + Mac VideoToolbox) / Raw (experimental emulator-host RGBA + Mac VideoToolbox).
- **Input:** Auto / scrcpy / Current (Mac mouse events plus the existing serial-scoped ADB key/text commands).

Both default to **Auto**, which prefers a compatible scrcpy server that successfully starts for the selected emulator, and falls back to the existing method if unavailable. The popover shows actual methods and the fallback/error reason. Explicit **scrcpy** reports unavailability rather than silently choosing Current. A failed Auto attempt is latched for that connection, not retried in an idle loop; reselect/reconnect after fixing the installation. Capture can fall back separately while control continues through a control-only scrcpy session. iOS is unchanged.

Install scrcpy yourself if desired; Simwisp never installs or upgrades it. The private wire implementation is pinned to **scrcpy 5.0.1** and its matching **scrcpy-server** JAR. It detects Homebrew's Apple Silicon/Intel paths and PATH installs with a matching share directory. Other versions/missing JARs explain the failure and Auto uses Current. No Python, OpenCV, PyAV, FFmpeg executable or scrcpy desktop window is used. The existing Android SDK adb remains the device transport, always with the selected serial.

Selections are saved **per AVD in this browser**, keyed by the AVD name rather than the reusable emulator serial; other browsers keep independent preferences. Switching reconnects only that panel, cancels/releases its gesture, and joins the old scrcpy process before starting another. Closing, replacing, pausing or stopping the selected stream tears down its owned sockets/process/tunnel/JAR. Only the session's own forward port/file is removed, never another scrcpy session or the ADB server. Closed streams do not leave scrcpy running. The existing TLS, pairing, one-controller policy, TalkBack pane gate and browser WebCodecs pipeline remain in use.

Native capture forwards framed Baseline/no-B H.264 into AVCC without decoding/re-encoding on the Mac. Encoded scrcpy output is forwarded on arrival, not rate-limited again by the pull-based window encoder scheduler. Natural IDRs keep the same browser decoder; only source/session/configuration or reference-chain discontinuities advance its epoch. The FPS tooltip distinguishes configured target from measured sent FPS; `/api/sessions` also exposes `sent_fps` and source/queue/drop/reset counters. At most four encoded access units /8MiB are queued; losing any reference invalidates the chain until a new IDR. Recovery uses RESET_VIDEO with rate limiting. Resolution/rotation session metadata and epochs invalidate stale frames. scrcpy uses the Mac-window crop pixel budget as its long-edge limit, preserving the Android display aspect ratio and allowing codec-alignment rounding (not arbitrary stretching). Mac-window and both scrcpy sources share the same even-coded-pixel quality→bitrate formula, clamped to0.5–40Mbps. Emulator quality1 no longer has the experimental200kbps exception, CBR2/QP44 overrides or forced one-second keyframes. Both phone and emulator video explicitly request Baseline (which forbids B-frames) and otherwise use pinned scrcpy5.0.1 rate-control/QP/automatic-keyframe defaults; immediate decoder recovery remains unchanged. Simwisp no longer reads or writes debug.stagefright.enableshaping on any capture/input path. It does not silently reset a previous build's device-wide0 override: restoring that existing guest state is an owner-controlled operation. Requested-QP/mode/shaping diagnostics remain present as null, not a claim about the codec's actual accepted format or current guest property. A411×914 window requests max_size914 rather than the old1920 setting. Stable host-window resizing updates only that device’s video source after a350ms debounce; rotation alone does not restart it. Without a window, the source retains its last known window budget, or starts with the initial browser dimensions (414×920 fallback). Decoder-dimension feedback never changes this budget. Control-only scrcpy sessions do not restart for window resizing. Capture remains capped at the requested1–60FPS. Diagnostics include requested/actual dimensions, target bitrate, requested maxQP/mode (not proof of accepted format or measured per-frame QP) and encoded/keyframe byte counters; even CBR is a target, not a hard per-second traffic cap. The shared Mac/scrcpy frontend rate is actual received valid video-packet bytes divided by monotonic elapsed time (not an assumed1s timer tick), with a fresh window on reconnect. It counts the24-byte Simwisp frame header even for packets dropped before rendering, but excludes JSON/control/WebSocket/TLS/TCP overhead. Displayed KB/s and MB/s use decimal1000/1000000 bytes; this is not raw H.264 bitrate or total network-interface traffic. Rendered FPS is likewise normalized by elapsed time. User setting changes are debounced; sustained adaptive FPS/quality changes restart the owned encoder/session at most once per five seconds. Android MediaCodec may encode in software: lower CPU/latency and real headless/Safari behavior are not guaranteed by this integration.

**Emulator scrcpy Scaling:** x1 (default), x0.5 and x0.25 are persisted per AVD and exposed directly below Capture for scrcpy or Auto while it uses scrcpy. The unscaled budget remains authoritative Mac-window crop pixels, the last known crop when headless, or bounded initial browser dimensions; the factor is applied once before Android H.264 encoding through max_size, with codec aspect-ratio/alignment rules. Native unscaled-budget metadata survives scaled/headless reconnects, never inferred from decoder feedback, and is retired once a different backend supplies its unscaled pixels. Touch uses reported video coordinates, which scrcpy maps to the full display. The controls are hidden/inactive for Mac-window/JPEG/Raw and Auto's Mac fallback; those paths ignore even forged scale requests. Changing scale reconnects only the selected panel through existing joined teardown. Use `make test-android-emulator-scrcpy` for native and isolated HTTPS/WebCodecs/scale/input coverage.

**Emulator Raw (experimental, manual-only):** selects the emulator-host `EmulatorController/streamScreenshot` RGBA8888 API, bypassing both guest JPEG compression and Mac JPEG decoding. Auto never selects Raw, and Raw is not an input option. JPEG and all existing capture/input choices remain available. The final Quality/FPS controls, hardware-preferred VideoToolbox H.264 encoder, 3600-frame GOP, explicit recovery and browser transport are shared with Mac-window/JPEG. Scrcpy input stays independent and control-only; this capture source performs no ADB capture, guest installation, root request, shaping-property change or input RPC.

Raw discovers only private, current-user emulator runtime records matching the selected emulator serial and a live QEMU PID. It requires exactly one authenticated local endpoint with an existing Bearer token; missing/ambiguous identity, incompatible HTTP/2/authentication, malformed images or transport failure fail visibly and latch until reconnect/resume. It never edits emulator credentials/JWT/JWKS, accepts a browser-provided endpoint or token, or falls back to another capture mode. One persistent macOS `/usr/bin/curl` HTTP/2 client owns each raw stream; no Node/Python/gRPC package is installed or needed at runtime. Curl config/proxies are disabled. The token goes through a private stdin pipe, not argv, a file, a URL, diagnostics or logs. Only a tiny non-secret screenshot request is stored in an owned0700 temporary directory (file0600); closing/replacing/pausing/stopping joins only the owned process and encoder and removes it. Tests use existing Node22/Chrome and an owned loopback HTTP/2 peer, not a real emulator.

The source is change-driven. The receiver validates uncompressed gRPC/protobuf framing, RGBA8888/display0, dimensions/byte count, sequence and timestamp bounds, with at most4096pixels on either edge and32MiB of packed pixels per image; oversized images fail instead of silently changing resolution. It uses one reusable64KiB read buffer and at most four bounded, rounded message slabs (32MiB+64KiB each at the absolute limit), including all checked-out owners. Immutable protobuf/pixel ranges retain their slab until the last user releases it, avoiding full-message and full-pixel extraction copies. One replaceable pending image and one encode in flight remain; a newly consumed source version is rendered once into an immutable encoder-owned BGRA pixel buffer. Static repeats submit that same prepared buffer to VideoToolbox without re-rendering, but still create new H.264 frames. A newer same-size image replaces the prepared buffer, not the encoder. The existing three-buffer pixel-pool allocation limit, sRGB/alpha composition and even-dimension padding remain unchanged. This is reduced-copy, not end-to-end zero-copy. The API supplies an already display-oriented packed bitmap; the Mac preserves its left-to-right/top-to-bottom row layout without an extra mirror, row-shuffle or rotation. The installed proto has a legacy “bottom up” comment, but applying another vertical flip inverted the real emulator output. Regression fixtures use four asymmetric corners matching the observed bitmap layout. No emulator display/rotation settings are changed. Window-size changes use the existing350ms budget debounce; losing a window retains the last or initial browser budget (414×920 fallback). Actual raw dimensions may differ slightly due to aspect-ratio scaling. Scrcpy input uses physical display coordinates, never raw/coded dimensions. Free RAW slabs shrink only after 64 consecutive non-empty messages request less than half the previous rounded capacity; spares larger than twice the largest request in that run are freed. In-flight leases remain valid, late returns use the current spare ceiling, and brief/moderate size changes retain reuse. This bounds retained high-water storage; it is not a claim that the reported overnight leak is solved.

With Data saver OFF, the Mac continuously produces NEW H.264 encodes/PTS from the latest pixels at the requested output ceiling, even while the raw API sends nothing; no encoded packet is replayed. With Data saver ON, no new producer update means no new encode, except explicit recovery. Raw does not run a full-image equality scan: duplicate producer updates can still encode. Output FPS/quality adaptation never restarts the raw stream or encoder; a real size/source change can. An inactive-display empty image disables old cached output until a fresh active image arrives. There is an8s initial-image deadline, but no frame-arrival timeout after a valid inactive/active notification: static streams may legitimately stay silent indefinitely. Socket/process termination and malformed replacement pixels invalidate the cache. Stream silence alone cannot distinguish a genuinely static display from a stuck producer; frame age remains honest, with no synthetic capture heartbeats/counters.

`/api/sessions` exposes separate source-frame/raw-pixel-byte, superseded-image, encoder-creation, new H.264/cached-image encode, prepared-pixel-buffer, receive-storage allocation/reuse, queue and source-age diagnostics. Preparation counts consumed source versions, not encoded repeats; receive allocations are cumulative and can increase after genuine size growth while live storage remains bounded. Zero JPEG encode/decode counters identify the removed stages. Local RGBA traffic is **not** the browser's H.264 bandwidth counter: at410×911×4×60 it is about89.6MB/s, scales with pixels/update rate, and may incur substantial protobuf/pipe/copy overhead. The upstream API has no requested-FPS cap; output pacing bounds Mac encodes, not emulator render events or local raw traffic. **Lower total CPU, 60 distinct motion frames/sec, end-to-end latency, hidden/minimized/headless real-emulator behavior and Safari/VPN acceptance remain unproven.** Existing emulator-host throughput results and synthetic integration tests are not those measurements. Do not call this zero-copy, an automatic JPEG replacement, or a measured CPU improvement.

The sidebar always groups real devices first, then booting/running simulators and emulators, retaining relative order within each group and respecting the project filter. Phones default to **JPEG** capture and **scrcpy control-only** input; an explicit **scrcpy** capture choice instead encodes H.264 on the phone and forwards it to the browser without JPEG or Mac re-encoding. The helper creates one persistent RGBA ImageReader mirror and consumes only newly produced buffers, capped at the requested1–60FPS without catch-up bursts. Image availability wakes a handler; acquireLatestImage drops superseded buffers. Three producer buffers, one reusable packed RGBA buffer/Bitmap and one bounded JPEG buffer limit work and allocations. RGBA row padding is stripped without swapping channels; each acquired image is released before JPEG compression or a blocked ADB write. Display dimensions/rotation/activity are checked every250ms and a geometry change releases/recreates the mirror. A missing initial frame fails after5s. While the display is static,1s bounded monotonic SWH1 heartbeats keep the8s host read deadline and10s stalled-writer watchdog alive; heartbeats never increment source-frame counts, mark capture ready or refresh source frame age. An idle mirror may produce zero fresh Android frames/sec. **With Data saver OFF, the Mac still encodes/sends at the requested FPS using the latest available decoded image, just like Mac window.** Every newer received JPEG replaces it; identical JPEG bytes reuse the decoded image without another ImageIO decode. Each H.264 frame is a new VideoToolbox encode with a new timestamp/reference state, never a replayed encoded packet. **Only Data saver ON suppresses unchanged image encodes and may idle at0FPS**; an explicit recovery/keyframe request may send one new IDR from the current image. This preserves event-driven Android capture/JPEG work, not zero Mac encode/network cost. The host retains one replaceable pending JPEG and one decoded image, with at most one decode/encode/write in flight; Mac-side encode pacing compensates small timer jitter without accumulating drift, and rebases missed deadlines without catch-up bursts and consumes pending JPEGs only on admitted work. The most recent image remains usable across static periods while framed transport is healthy; failure, cancellation or the8s transport deadline disables the cache. Corrupt newly received JPEGs fail visibly instead of freezing on older pixels. Source frames/JPEG bytes, idle heartbeats, JPEG decodes, cached-image H.264 encodes, total H.264 encodes and actual sent/rendered FPS are separate counters; re-encoding never increments fresh-source counts or resets source-frame age. Data saver JPEG byte equality is not a universal visual-change detector. Motion throughput and CPU savings require measurement. Intermediate JPEG traffic is local and is not the browser's bandwidth counter. Rotation updates frame dimensions/decoder epoch and refreshes control-only input geometry without changing the gesture's frozen coordinates. Host-window resizing updates the long-edge budget after350ms; without a window it retains the last budget or initial browser dimensions (414×920 fallback), capped at4096. The helper follows the user-requested FPS cap, not transient adaptive output FPS. Congestion/recovery changes only local H.264 pacing/bitrate, preserving the mirror, cached pixels and native encoder. Explicit user FPS-cap changes remain debounced source reconfigurations; actual geometry/lifecycle/failure changes still replace invalid state. Quality changes need no source restart. JPEG diagnostics include native encoder creation counts.

Each JPEG session owns a unique private /data/local/tmp directory, JAR, PID and process name. Closing, replacing, pausing, disconnecting or stopping joins only that source/encoder and removes its files; signals verify the exact owned process identity. Remote file removal is best-effort if ADB/the emulator has disconnected; the helper also exits on a broken pipe or stalled-output watchdog. No APK/system installation, ADB server restart, clipboard/power change or global cleanup is used. Current touch input still requires its host window/permissions. Hidden/minimized/headless capture, sustained real-motion quality/latency and Safari acceptance are **not certified** by synthetic integration tests; JPEG is a lossy intermediate. Prior Android-side benchmarks at~410×914 demonstrated60 fresh capture/JPEG completions per second at Q80/Q95, not this integrated Q70 path or60 distinct app-rendered updates. Rotate uses scrcpy with direct capture; with Mac-window capture it retains the emulator-skin rotation command so the window geometry stays aligned. Control-only mode reads actual Android display dimensions once at startup/reconnect. Browser/window dimensions are hints, never trusted Android coordinates. ### React Native console

Run a development Metro server on this Mac at the standard **127.0.0.1:8081** endpoint and stream its simulator/emulator in Simwisp. When a compatible target is discovered, a custom icon appears at the end of that device's lower control bar. Its tooltip/accessibility label is exactly **React-Native console**. Discovery is shared across all streamed devices: immediately on active stream startup (coalesced/debounced during reconnects), then every 30 seconds after the preceding scan completes. It reads metadata only; absent Metro means no icon, and removing the final active stream stops the discovery timer. Failed scans preserve the last successful buttons.

Android targets also match the exact React Native model/OS label (for example, **sdk_gphone64_arm64 - 16 - API 36**) read using serial-scoped ADB system properties during the existing eight-second device-tool cache refresh. The AVD display name and emulator serial remain unchanged. Missing/failed/invalid property reads supply no alias. Identical labels across running emulators require the picker even if only one has an open browser view; a peer with unreadable model properties also makes alias-based mapping inconclusive and requires confirmation; an explicit advertised serial takes precedence and attachment still requires the selected active stream.

Click the icon to create/focus a **Console · App · Device** tab in the existing Terminal popup. Multiple targets or indistinguishable devices require an explicit picker; no first result is silently selected. Confirmed bindings and open-tab descriptors are session-scoped. Console-only use does **not** load xterm, create a shell, require Mac terminal access, or consume the independent eight-terminal quota. The **+** action remains Mac-terminal-only; up to eight console tabs/active upstream targets are allowed independently. Mixed tabs share font size, resize, pinning and the scrolling tab strip.

Console tabs show bounded read-only JavaScript logs/info/warnings/errors and exceptions with expandable source/stack details. Local filters/search, Pause/Resume, Clear and Auto-scroll do not send commands to the app. Pause continues bounded collection; inactive or collapsed panes do no log-row rendering. Evicted log references are released immediately (including reserved object-budget trims), independently of array-slot compaction. Retention is at most 5,000 entries/5 MiB per tab and 300 live log rows in a windowed Older/Newer view; dropped entries are counted. Resizing preserves the retained page and reading position; Auto-scroll stays pinned to the newest entry until the user scrolls away or explicitly disables it. Older/Newer navigate the retained ranges independently of the top visible row. No console history is persisted. Closing a tab or explicitly removing its simulator ends the subscription; the last subscriber closes the shared upstream connection. Transient video reconnects retain tabs. Browser reload restores explicitly opened console descriptors without saving log contents or automatically choosing a different app.

Objects/functions/arrays show the supplied inline preview and independent native disclosure arrows, like React Native DevTools. **Only expanding an object** requests its own property descriptors via **Runtime.getProperties**; nested values and [[Prototype]] have separate lazy disclosures. Buffered/replayed objects can be inspected while their runtime references remain valid. Properties are evaluated at expansion time, **not frozen at logging time**. Already loaded tree pages are reused on collapse/reopen; an evicted view can be explicitly expanded/retried again. Runtime/context changes and expired references report unavailability, never fabricate historical values. Object expansion does not change the existing source/stack disclosure. Strings/values/names are always inserted as text; no getters/functions are explicitly invoked by Simwisp and no evaluate/callFunctionOn/debugger commands are exposed. Legacy/runtime-specific Hermes property inspection itself may execute getters; descriptor behavior and actual installed RN/Hermes/Safari compatibility still require manual validation.

Native object IDs stay private: opaque handles are scoped to an upstream generation and only admitted after delivery to the requesting subscriber. Limits: 16 admitted 4KiB client messages at a time (including coalesced log/property ACKs); 4,096 handles per upstream/subscriber; one property result/request/ACK per subscriber, at most 64 upstream calls, 5-second request and 10-second result-ACK deadlines; 1,000 own +128 internal descriptors and a 128KiB response cap with explicit truncation. The browser caches at most 128 property responses/1MiB **inside the existing combined 5MiB log budget**; it renders 100 fields/page, at most 2,000 property rows, with bounded depth/cycle handling. No eager snapshots, property polling or persisted object history. Clear/tab close/disconnect cancel queued work; stale callbacks cannot revive cleared views.

The native backend alone queries Metro's loopback /json/list and resolves private inspector URLs; the remote browser never receives or submits debugger URLs. Discovery has a 5-second/1 MiB/64-target limit and coalesces concurrent calls. Dedicated authenticated, origin-checked **/ws/metro-console** traffic is isolated from video/input and **/ws/pty**, with one read-only **Runtime.enable** per upstream connection and allowlisted, user-triggered **Runtime.getProperties** requests. No evaluate, debugger, explicit accessor/function evaluation, reload, LAN/port scan, native logs or global attach menu is exposed. Pending output is independently limited to 512 entries/1 MiB per subscriber, using one outstanding entry ACK; slow subscribers cannot enqueue unbounded writes or block other targets. Runtime reconnects use capped backoff/shared metadata, never per-tab discovery polls. No debugger-takeover commands are sent; refused attachment is reported. Inspector ownership behavior is runtime/version-specific and still needs manual validation.

Real React Native/Hermes versions may expose different metadata or refuse a second inspector. V1 deliberately supports the standard loopback endpoint only. Missing/inconclusive mapping or attachment reports unavailability rather than guessing. Actual application/runtime compatibility and Safari behavior still need owner validation after deliberate rebuild/relaunch and browser reload. The localhost transport exception does not relax Simwisp's browser HTTPS/WSS/auth policy or allow client-selected hosts.

### Stop a simulator

The power icon beside each running device in **Your devices** asks for confirmation before shutting it down. The bottom toolbar's **Close** button only closes that browser view; it does not stop the device. Stop targets exactly the selected iOS UDID (`simctl shutdown <UDID>`) or Android emulator serial (`adb -s <serial> emu kill`). Other devices, browser views and Mac terminals are not stopped. Unsaved app state may be lost.

The selected view and inspector are removed, its saved open-view entry is cleared, and the device list refreshes once after success. Existing viewers receive an intentional-stop notification rather than reconnecting. Native shutdown waits for that device's capture cleanup, including a recently disconnected/replaced view or pending startup. If cleanup has not settled within 20 seconds, the request fails without scheduling a later shutdown; refresh and retry. A failed shutdown leaves the row available for reopening or retrying, with an error rather than automatic reconnection.

Android Stop distinguishes command acceptance from completion. After a successful serial-targeted kill, it waits up to **eight monotonic seconds**, including inventory command time, for that exact serial to disappear from a valid all-state ADB inventory. If it remains (including offline/unauthorized), or inventory checks fail, the UI shows a neutral **Stop requested; awaiting confirmation** rather than claiming shutdown failed or succeeded. **Refresh devices** performs one fresh authenticated read-only status check for that pending action; confirmed serial absence changes the message to **Stopped**. Offline disappearance from the running-device list alone is not confirmation. No kill is repeated and no background status poll is retained. A further successful refresh dismisses the resolved message; fresh refresh also dismisses prior command errors/window warnings. Failed, cached or stale refresh responses cannot clear/reclassify a newer action. A genuine kill-command failure still shows an error.

On iOS, Stop confirms the selected UUID is shut down, pauses300ms once, then checks verified current-user `SimRenderServer` processes. If any remain, Simulator.app stays open. If none remain, the check is repeated inside the pending-launch guard and the whole Simulator.app is closed, without AX/CG window matching or requiring other headless simulators to shut down. Process reads fail closed. Application identity includes PID and launch date; normal termination is requested only for Simulator.app and exit is confirmed with a bounded, action-scoped notification wait. There is no renderer kill, force kill, recurring timer or background polling. A close refusal or failed process query is reported. Headless iOS uses the same process signal for its conditional Yes/No warning, rechecks consent on the server, closes the whole GUI before boot, opens that exact UUID directly, then refreshes the full device list only after its first displayed video frame. Cancel sends no boot/quit request. Browser panel Close remains view-only.

### Authenticator pairing (optional)

The first launch of this version adds a disabled `pairing` group to `~/Library/Application Support/Simwisp/settings.json`, preserving the existing token, preferences and unknown top-level owner fields. You can also add the following group **alongside the existing fields**. Keep the existing `pairingToken`: it authorizes links and existing browser cookies. Restart Simwisp after editing; settings are not polled or hot-reloaded.

```json
"pairing": {
  "totpSecret": null,
  "rateLimits": {
    "postsPerIPPerMinute": 2,
    "totpFailuresPerIPPerMinute": 2,
    "ipCooldownSeconds": [600, 1800, 3600],
    "repeatWindowSeconds": 1800,
    "globalTotpFailuresPerHour": 2,
    "globalTotpLockoutSeconds": 3600
  }
}
```

Replace `null` with a **unique, private Base32 secret containing 20–64 bytes**, generated with a trusted local tool/password manager; enroll the same seed in your authenticator using **SHA-1, six digits, 30 seconds**. Do not use public test/example seeds or online key generators. Missing, null or blank seeds disable TOTP and hide its browser choice. Settings are owner-only (`0600`); neither the seed nor accepted codes are returned by the server or written to logs. Saved settings are pretty-printed, keeping seed and limits together. Old settings remain compatible and their pairing token is preserved. Invalid JSON/types are not silently replaced with new credentials; invalid seeds/limits prevent server startup until corrected.

The unauthenticated screen offers **Pairing link** or **Authenticator code** when configured. The server accepts the current step ±1 for clock skew and exchanges either credential for the same Secure/HttpOnly/SameSite Strict browser cookie. A successfully accepted step cannot be reused, including after restart; wait for a fresh step when pairing another browser. This is an **alternative credential, not two-factor authentication**. With terminals enabled, either method grants Mac-user shell access. TLS encrypts the transport, but TOTP does not prevent real-time phishing; keep pairing links and trusted clients private.

Limits apply only to `POST /api/pair`, never simulator/terminal traffic or already-paired requests:

- **Two POSTs in a rolling 60 seconds per socket IP**, including valid/invalid link and TOTP requests. Forwarded headers and changing source ports do not change identity; IPv6 identities group by /64 if used by the transport.
- **Two failed TOTP verifications in 60 seconds/IP** start a 10-minute cooldown, escalating to 30 then 60 minutes. The repeat window starts **when the previous cooldown ends**; after 30 quiet post-expiry minutes the tier resets. Successful TOTP clears that IP's failure streak/tier, not global failure history.
- **Two failed TOTP verifications across all IPs in a rolling hour** block new TOTP pairing for **one hour from the triggering failure**. Two typos or another LAN client can intentionally cause this lockout. At these defaults it normally dominates the shorter IP cooldowns. Link pairing retains its normal POST budget, and existing browser sessions remain usable.
- Reject throttled attempts immediately with `429` and `Retry-After`; blocked requests never extend cooldown/global deadlines or count as additional credential failures. The second incorrect credential returns generic `401`, with subsequent TOTP attempts throttled. All counts/durations above are editable; counts must be 1–1000, durations 1–604800 seconds, and the three IP cooldowns ordered.

Replay protection, global failed-attempt history and the global lock deadline persist in owner-only `pairing-state.json` next to settings, scoped to the decoded seed. Per-IP state is a bounded in-memory cache, expiring only on pairing requests; restarting resets IP budgets but not the persisted global/replay protection. Authentication and atomic state writes run on a separate serial queue, with **no timer, background polling or network/capture-queue sleep**. An unreadable/unwritable state file fails TOTP closed (`503`), while link pairing still works. Do not delete/edit state to bypass limits; repair permissions on the Mac if needed, or wait for lock expiry. `make test` runs deterministic pairing tests (RFC TOTP vectors, migration, boundaries, cooldowns, restart persistence, replay and fail-closed behavior) without launching the app.

## Privacy and pairing

Simwisp serves the workspace and simulator streams directly from your Mac; it does not need a cloud service.

- Pairing links authorize simulator control and, when explicitly enabled on the Mac, host shell access. Treat them as private credentials.
- APIs require authentication, and WebSocket upgrades and mutating requests enforce same-origin checks.
- Browser authentication uses a Secure, HttpOnly, SameSite Strict cookie.
- Workspace, video and terminal traffic use **HTTPS/WSS**, with deliberate local-CA trust on each client. Keep pairing links private and do not expose the port directly to the internet.
- Settings, including the pairing token, are stored outside the repository at `~/Library/Application Support/Simwisp/settings.json`.

## Android TalkBack inspector

On an Android stream, the **A11y** control opens an accessibility pane below the simulator. Composed TTS fallback is labeled separately from exact `action=SPEAK`. Password-node content is hidden; no raw logs/history are persisted.

Monitoring is native, bounded and readiness-driven: one serial-targeted ADB reader exists only when that pane is open **and its Android stream is active**. Closing the pane while video continues, pausing/hiding the stream, losing its window, disconnecting, replacing the controller or stopping the server cancels reading and terminates the child. No background logcat reader, parser, polling timer or accessibility sending remains when monitoring is off. Inspector JS/CSS loads locally only on first open. Reconnection opts in only for a pane that is still open. The native popup reports listening/recent sending/paused/error in that Android session's existing details.

## Performance and lifecycle

Streaming uses H.264 Baseline without B-frames, with an explicit zero-reorder SPS for low-latency WebCodecs output. The existing 1–95 quality control selects a resolution-scaled target bitrate (about 6 Mbps at 1080×1920/q20), not image compression. Hardware encoding is preferred where available. Capture keeps the latest pixels; one encode and one local socket write may be active per stream, backed by a three-buffer pixel pool. Native one-shot deadlines pace at the requested FPS ceiling, skipping missed deadlines rather than replaying a burst. Mac-window, JPEG and RAW local encoders preserve their scheduled phase for timer delays smaller than one quarter of a frame, rather than adding each small delay to every following deadline; larger stalls rebase once without catch-up bursts. There is **no per-frame video ACK gate**: the browser decodes reference frames independently, keeps at most one decoded output for the next animation frame, and closes every superseded, displayed or stale VideoFrame. Receiver feedback is cumulative every **250 ms**, not a permission to send each next frame. Terminal parsing ACKs are separate and unchanged.

Mac-window, Emulator JPEG and Emulator Raw capture share a **3600-frame automatic keyframe interval** (about60seconds at60FPS; longer at lower cadence), with no additional one-second time cap. Repeated short-GOP IDRs can replace a refined static image with a coarsely quantized reference at low bitrate; lengthening the GOP avoids that pumping without extra capture/decoding or changing requested FPS, JPEG70 or the quality→bitrate curve. Startup, real source/geometry changes and explicit decoder/transport recovery still force immediate keyframes; they never wait for the automatic interval. Scrcpy video uses the pinned upstream automatic keyframe policy on both emulator and phone, with immediate explicit recovery.

Video transport debt is bounded at **120 frames / 1 MiB**, with a single larger IDR allowed alone within the existing hard packet/socket limits. Outstanding metadata survives encoder-epoch changes; old receipts may retire delivered bytes but cannot tune a replacement decoder. Decoder backlog is bounded at **48 pending frames / 8 MiB** (one larger packet may enter alone) and **16 decode inputs**, including the initial asynchronous capability probe. Native capability notification replays settings/readiness after asynchronous device discovery. If admission fails after encoding a P-frame, the server forces a fresh IDR instead of continuing a broken reference chain. This routine Mac/JPEG reference refresh, and a Data saver toggle, keep the same decoder epoch/configuration; genuine source changes, pause/resume and an explicit browser decoder-recovery request still advance the epoch. Outstanding transport debt survives either kind of recovery. Decode overload or **more than two seconds without pending output** resets the decoder and requests a new epoch/IDR; heartbeats cannot hide that stall, including at 1 FPS or in Data saver. An unanswered recovery or unreceived/blocked native write after about **three seconds** reconnects rather than retaining indefinite stale video. No routine decoder flush is used. Server/client pacing versions are negotiated; rebuild the app and reload existing browser tabs together when activating this change.

Data saver skips unchanged images on Mac-window and JPEG capture. With it off, both encode the latest available image continuously at the configured cadence, even if the source has not changed. Neither replays cached encoded P-frames. The upstream scrcpy display source is change-driven even when this setting is off; its finite idle-frame repetition is not a continuous 60fps source. Simwisp reports actual transmitted/rendered frames, never inflates FPS by repainting a cached image. Continuous static-screen encoded output would require additional source support; use Mac window capture when that behavior is required. Idle Data saver with no pending output does not trigger recovery. Slow local writes, finite transport budgets and receiver overload can reduce FPS/bitrate quality; sustained healthy feedback restores them up to the user's targets. TCP can still head-of-line block on loss: **60 FPS and low live latency are targets, not guarantees**, and this architecture alone does not certify Safari or real internet performance. Text sharpness, bandwidth, GPU cost and latency depend on workload and client.

Capture teardown tracks startup, running and terminal states. Closing a simulator window ends only that capture; already-stopped streams are not stopped again, failed starts detach their output, and overlapping cleanup callers await the same teardown. Unexpected cleanup failures remain visible in logs and `/api/status` capture `last_cleanup_error`, but do not block capture startup for unrelated devices.

When the final simulator streaming client disconnects, capture is torn down and the discovery timer is cancelled. The menu-bar popup's monitoring timer exists only while the popup is visible/key. Browser device-list requests still perform on-demand discovery.

Historical JPEG-build no-terminal idle lifecycle verification measured approximately **0.01–0.02% of one CPU core** on the development Mac. A later explicitly sampled terminal review measured **0.0423% with one idle terminal** and **0.0444% with two**, with unchanged PTY I/O counters and no capture demand. Sampling itself adds work; these are short observations, not universal CPU guarantees. The panel's CPU display uses **100% = one core**; measurements are app-process usage, not total simulator or system usage.

Terminal connections never count as simulator streaming demand. PTY reads/writes and child exits are dispatch-event driven on a separate queue; idle terminals do not poll. Cursor blinking and smooth scrolling are disabled. Shell output waits for browser parsing acknowledgements, with at most one bounded chunk in flight; input and replay buffers are capped at 64 KiB. Connected terminal sockets use a low-frequency keepalive; disconnected retention and ACK deadlines are one-shot timers. Actual shell commands naturally consume CPU when doing work.

Only one Simwisp app instance may run at a time; duplicate launches exit without starting another server.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Certificate warning / insecure context | Explicitly trust the exported public CA; use its matching HTTPS name/IP, not HTTP or a warning bypass |
| H.264 unsupported | Update/use a browser with H.264 WebCodecs support; no fallback is retained |
| No frames / device window unavailable | Screen Recording permission; simulator window open and unminimized |
| Frames work, input does not | Accessibility permission; selected simulator window and focus |
| Android devices missing | SDK path, emulator running, and the SDK's `adb devices` output |
| Repeated reconnects | Another browser may be controlling the same device |
| Port already in use | Quit the existing Simwisp instance or choose another `--port` |
| New launch options have no effect | `open` reused an existing instance; quit and relaunch |
| Capture stopped / window closed | Reopen the simulator window; its stream can restart without quitting Simwisp |
| Unexpected capture cleanup error | Inspect `/api/status` capture `last_cleanup_error` and logs; domain/code identify the affected capture |

## Development status

**Early development build — version 0.2.0.** Live capture, pairing, multi-device streaming, disconnect/reconnect, and idle cleanup have been exercised on Apple Silicon. The host-architecture build recipe also supports compiling on Intel, but Intel runtime behavior has not been verified.

Some native control combinations still need broader verification, particularly Android rotation and iOS text entry. Terminal PTY/security/lifecycle and desktop/mobile browser controls have been exercised on Apple Silicon. Terminal access is optional and disabled by default; the old JPEG pipeline has been removed rather than kept as a fallback.

The repository contains production source and browser resources only; generated logs, diagnostics, review reports, and app bundles are not checked in.

Unchanged in-place source rows are compared without rewriting them under the producer lock; distinct immutable leases still receive every row.
